# 项目 Skill 的编写与接入

建立或重构项目运维 Skill 时读取。仅修正某条已知命令时，直接修改该命令的所属位置。

## 形成项目入口

- 沿用已有 Skill 名称；新建时使用能区分项目与用途的名称。实体默认放在 `tools/skills/<skill-name>/`，项目或用户另有约定时沿用对应位置。
- 先确认实际工作流，再填写模板。省略缺失或无关的章节，替换全部示意内容。迁移位置时同步原入口、发现链接与引用。
- `description` 写明具体触发任务，例如构建、启动或打包。通常的源码修改按项目指令执行；只有需要该运维能力时加载 Skill。
- 每个项目维护自己的路径、配置和结论。详细契约与操作说明引用已有项目文档；短命令没有其他正文归属时可直接放在 Skill。
- 命令以代码、配置、CI 或现有文档为依据，写成从仓库根目录执行的代码块。CI 的触发条件和执行平台按实际配置记录。
- 链接相对于生成文件解析。位于 `tools/skills/<skill-name>/SKILL.md` 时，项目根的 `docs/` 链接以 `../../../docs/` 开头。

## 模板

下列占位符只用于编写示意；生成结果填写真实内容，并删除不适用条目。

````markdown
---
name: <项目>-ops
description: <项目>的<实际工作流>。在<具体操作任务>时使用。
---

# <项目> 运维

## 必要约束

- <影响这些操作的项目边界、状态约束或环境要求>。
- 版本、端口、进程和部署目标：<配置路径或获取方法>。

## 按任务读取

- <某项操作>之前：<必要短提示>，读取 [操作说明](../../../docs/<实际文件>.md)。
- 触发项目验证要求时：读取 [验证说明](../../../docs/<实际文件>.md) 中对应要求。
- 当前任务包含已授权发布时：读取 [发布说明](../../../docs/<实际文件>.md)。

## 直接入口

<此处只放由本 Skill 维护的短命令；已有说明维护的命令通过上方链接读取。>

从仓库根目录执行：

```text
<实际命令>
```

## 运行与恢复

- 运行前查看并复用已有进程、任务和结果；操作限定于本项目、本任务。
- 用户要求运行时，完成必要准备、构建、启动和排障，按实际运行状态汇报。
- 写操作超时或断连时，先读取目标状态或已有操作标识，再决定重发。

## 输出与凭据

- 产物：<位置和获取方法>。
- 凭据：<现有私有配置的读取位置>。

## 维护

本次操作使说明或脚本失实时，修正对应位置；已确认的复用方法归入已有文档或脚本，一次性排障留在对话。
````

## 操作细节与辅助脚本

- 版本、PID、地址和部署目标记录获取方法，执行时读取实际值。凭据内容保存在既有私有配置中，文档仅记录读取位置。
- 重复或易错的多步操作优先复用现有脚本；确需新建时放在 Skill 的 `scripts/`。按实际需要提供 `status`、`build`、`test`、`start`、`stop`、`logs` 或 `deploy`，单条命令足够时直接使用命令。
- 脚本参数表达项目和操作边界，成功输出简短结果，失败输出原因与位置。执行验证、发布或部署的条件来自当前任务和项目要求。
- 涉及服务端重新实现时，将已确认的协议、资源处理和客户端操作接入现有工具；待确认行为标为“未知”，取得日志、抓包或源码证据后实现。
- 接入 agent 实际支持的 Skill 发现目录；Windows 的目录链接可使用目录联接。链接指向实体目录，变更前检查已有目标与调用方。发现目录由当前客户端文档和环境确定。
- 链接创建失败时，在项目入口写明 Skill 路径与适用任务。用户要求稍后安装时，交付项目内文件即可；接入完成后核对发现路径实际指向的内容。
