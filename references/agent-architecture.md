# 渐进式项目说明架构

初始化、精简或重构 agent 指令及项目文档结构时读取。目标是让入口提供足够的判断依据，详情在任务需要时加载。

## 按职责确定归属

| 内容 | 正文归属 | 读取时机 |
|---|---|---|
| 跨项目偏好、任务范围、授权规则 | 用户全局指令 | 会话开始时 |
| 项目始终适用的边界、短小高频事实、任务路由 | 项目入口 | 进入项目时 |
| 某个子系统独有的约束 | 既有模块文档或作用域明确的目录指令 | 处理该模块前 |
| 架构、接口、持久化、验证、发布细节 | 对应项目文档 | 执行受其约束的动作前 |
| 可复用的构建、运行和排障流程 | 项目 Skill 与必要脚本 | 执行对应操作前 |
| 一次性过程、尚未确认的判断 | 当前任务记录 | 当前任务需要时 |

原文通常一起使用且已经简短时，直接合并重复表述即可。内容有独立触发条件、拆分能减少无关读取时，再单独成文。正文保留一处；入口可保留必要短提示和链接。

## 迁移原有指令

1. 完整阅读待重构的指令，确认已有引用、适用范围及读取它的脚本或客户端。将原有规则在工作记录中对应到保留、合并或迁移的位置。
2. 先处理冲突：明确的用户要求及适用的项目约束决定行为，命令和路径结合代码、配置与运行证据核对。对仍影响结果的未知分歧询问用户，其余工作继续。
3. 全局约束留在全局入口；项目约束落在项目内。用户要求改变规则时按其要求修改；结构整理保留原有义务强度、执行时机、适用范围与例外。
4. 根据下一节为迁移内容补充可识别的路由，再更新原引用和调用方。已有脚本读取的字面格式应一并核对。
5. 比对原规则与新归属、检查引用和真实读取范围。工作记录用于本次核对；长期文档只保存以后仍有用途的知识。

## 写清读取触发条件

每条路由给出“可观察的任务或对象 + 必要短提示 + 何时读取 + 具体路径”。agent 应能从当前任务判断是否命中，并在相关动作前读到约束。

- 小范围源码修改：阅读对应代码与已经适用的指令。
- 修改模块依赖、公用接口或持久化：修改前读取相关契约。
- 构建、运行或排障：执行前读取对应运维入口。
- 验证与发布：任务触发已有验证要求或已授权发布时读取相应说明。

项目入口示意如下。只保留真实存在且适用的条目，将路径和摘要替换为项目事实。

```markdown
# 项目工作入口

<项目用途及始终需要遵守的边界。>

- 修改模块依赖、公用接口或持久化前：读取 [相关契约](docs/ARCHITECTURE.md) 的对应部分。
- 构建、运行或排障前：读取 [项目运维 Skill](tools/skills/<项目>-ops/SKILL.md)。
- 触发项目验证要求时：读取 [验证说明](docs/VALIDATION.md) 中对应流程与已有结果。
- 当前任务包含已授权发布时：读取 [发布说明](docs/RELEASING.md)。

本次改动使入口、文档或 Skill 失实时，同批更新所属位置。确认且可复用的知识写入已有正文，一次性排障留在对话。
```

## 文档约定

沿用项目已有分工；需要补充时，从下表选择实际需要的文档。按任务读取对应部分，按缺口建立必要文件。

| 默认位置 | 读者与内容 |
|---|---|
| `README.md` | 用户：功能、系统要求、构建运行、命令行、文档索引 |
| `CONTRIBUTING.md` | 开发者：环境、模块边界摘要、PR 必跑命令、提交规范 |
| `docs/ARCHITECTURE.md` | 修改代码的人：模块、契约、边界和扩展规则 |
| `docs/VALIDATION.md` | 验证者：当前命令、最近结果、实测范围 |
| `docs/RELEASING.md` | 维护者：版本来源、发布条件与失败重试 |
| `CHANGELOG.md` | 使用者与维护者：变更及历史结果，待发布内容保留在 `Unreleased` |
| `tools/<工具>/README.md` | 工具使用者：用途、仓库根目录命令和输出文件 |

命令用可复制的代码块表示，工作目录统一为仓库根目录。版本值由既有唯一来源维护；新建产物目录默认采用被 gitignore 的 `artifacts/`。验证记录保留当前命令和最近一次结果：日期、提交、环境、覆盖项及“已验证：…。未验证：…。”；历史结果归入变更记录或项目既有历史位置。

入口的本机保存或版本跟踪方式遵循用户要求和项目约定；既有协作文件保留相应用途。私有机器信息留在私有配置，公共模板使用可移植路径。

## 跨工具接入

先确认目标客户端实际加载的文件、作用域和 Skill 发现位置，再建立必要入口。共用 Markdown 正文；平台入口仅承载接入所需内容。

| 客户端 | 接入方式 |
|---|---|
| Codex | 使用实际生效的 `AGENTS.md` 指令链。启动时按项目根至当前目录发现；从根目录处理其他子树时，通过项目路由读取该子树的适用约束。 |
| Claude Code | 检查当前会话是否已读取项目 `AGENTS.md`。需要兼容入口时，可在同目录 `CLAUDE.md` 使用 `@AGENTS.md` 导入简短入口；专项详情仍以条件链接读取。 |
| 其他 agent | 沿用其已验证的入口与原生格式，链接同一份正文；客户端明确支持的目录或路径规则按其实际作用域使用。 |

普通 Markdown 链接是 agent 在触发时主动读取的指引。Claude 的 `@import` 会随引用者一起加载；省上下文的详情应放在按需链接、Skill 或客户端确认支持的条件规则中。新增 frontmatter 仅使用目标客户端实际支持的字段。

接入后核对文件路径、链接目标与实际内容。声明“客户端已加载”时，应有客户端读取证据；文件检查结果按文件检查汇报。

## 任务内维护

- 命令、契约、路径或恢复方式发生变化时，修正对应正文以及受影响的引用；只有路由失效、职责混杂或用户要求整理时才调整结构。
- 新发现先确认来源与复用价值，再更新最贴近其职责的已有位置。项目事实留在项目，用户偏好由用户指令决定。
- 结构已经适合当前任务时，结束整理。文档维护的验证范围来自当前任务与项目要求。

加载机制依据：[Codex 指令](https://developers.openai.com/codex/guides/agents-md)、[Skill 按需加载](https://developers.openai.com/codex/skills)、[Claude 指令与导入](https://code.claude.com/docs/en/memory)。接入时以当前客户端文档和实际状态为准。
